# 架构与源码地图

业务链路：会议/论文/机构和公司资料 → WorkBuddy批次原文 → 复核/归类 → SQLite研究事实与证据 → 研究视图 → PI合作推荐 → 市场分配 → 销售跟进及推荐评价 → 人工复盘。

## 实际入口

workbench/index.html转到领域工作台/index.html。领域工作台有#topics、#conferences、#papers、#experts、#market、#sales。Biomarker内部入口跳../标志物视图/index.html#research。会议视图/index.html是CDS，ada.html是ADA；这些来源视图保留原路径。

## 关键文件

| 文件 | 职责 |
| --- | --- |
| workbench/领域工作台/src/template.html | 统一页面骨架及内嵌占位符 |
| src/app.js、style.css | 研究视图、路由、六入口、搜索、旧链接兼容 |
| src/weekly.js、weekly.css | 本周召开/新收录更新、独立周议题榜及日期归周 |

| src/sales.js、sales.css | 分配、账号范围、收藏、客户沟通及市场汇总 |
| src/recommendation-feedback.js、对应CSS | 资料有用性、历史/快照、独立草稿与质量汇总 |
| workbench/脚本/生成领域工作台.py | 只读拼接来源快照，内嵌成单文件HTML |
| workbench/脚本/生成会议总入口.py、生成领域热点相关脚本 | 会议目录/跨会议议题来源投影 |
| workbench/脚本/生成论文视图.py、生成标志物视图.py | 论文及Biomarker来源页面 |
| workbench/维护台、脚本/启动维护台.py | 现有本机CDS日程维护服务，不能当共享销售后端 |

src路径在表中均相对workbench/领域工作台。修改src后重新生成，单改index.html会在下一次生成丢失。

## 配置

研究领域与导航.json为6领域6入口；糖尿病统一议题映射.json保留来源→领域中性ID；PI已有评级.json为14人旧评级投影；销售协作原型.json为能力、演示模板、匹配规则与已存AI分析；会议更新记录.json暂未接入；WorkBuddy资料入库约定.md为采集契约。

## 技术边界

当前为buildless HTML/JS/CSS＋Python只读导出＋SQLite，无React/Vue或Node服务端。静态前端在同一浏览器共享localStorage，无身份认证。后续可逐步引入服务层，先保护存量ID、证据和业务数据，再调整工程目录，避免一次性重写研究统计。

旧文档/旧导入器有初期表数与绝对路径。当前打包验收用tools/verify_package.py；原核验领域框架.py验证当前研究导出。核验数据库.py是历史首轮冻结口径，核验摘要批次002.py还依赖原机历史备份，不能直接当可迁移总验收。

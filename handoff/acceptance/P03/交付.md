## 2. 目标与已完成
* **业务定性调整**：按最新业务明确要求，将权限架构聚焦精简为两大部分：
  1. **市场部（market）**：作为全局管理端，登录后拥有最高查看与管理权限，**可查看所有界面**（包括学术研究全部视图、全量 PI 推荐池、所有销售代表的分配记录、全员跟进反馈复盘统计），负责线索的创建、分配与跟进复盘。
  2. **销售代表（sales）**：分销售登录各自账号（如销售 A、销售 B），进入销售工作台后，**严格只能查看分配给本人的线索与自己的收藏夹/反馈**，禁止越权查看其他销售名下的线索，禁止查看市场未分配的草稿。
* **已完成事项**：
  1. **鉴权服务端精简调整 (`tools/auth_server.py`)**：
     * 去除冗余的独立 manager 角色，市场部人员登录后直接赋予全局查看所有界面的全量权限；
     * 保留真实 Token 鉴权（`Authorization: Bearer <token>`），基于高熵随机 Session Token 校验；
     * 销售代表数据严格按登录的 Token 身份进行服务端强制过滤；
     * 强制防身份冒充（防篡改）：提交沟通跟进与推荐评价时，落盘的 `author_id` 强制取自服务端认证用户，作废前端伪造参数。
  2. **前端工作台文案与逻辑精简 (`workbench/领域工作台/src/sales.js`)**：
     * 角色模型精简为“市场部”与“销售代表”；
     * 市场部登录可查看全局所有界面与全量分配记录；
     * 重新编译生成静态工作台主文件 `workbench/领域工作台/index.html`。
  3. **自动化测试套件适配并通过 (`tools/test_p03_rbac.py`)**：
     * 7 大核心场景（未登录 401 拦截、Session 签发与过期、市场部全局可见性、销售代表个人线索隔离、跨销售越权写 403 拦截、防篡改 author_id 覆盖、跨人导出数据隔离）**100% 全部通过**；
     * 学术事实库 `marketing.db` 保持哈希 `645adc48...` 零改动、零污染。

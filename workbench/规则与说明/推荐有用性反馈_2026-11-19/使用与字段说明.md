# 推荐信息有用性反馈

日期：2026-11-19。入口：销售工作台 → 我的推荐 → 选择推荐。市场工作台 → 反馈复盘查看汇总。

## 本轮界面

推荐详情顶部增加“这条推荐对你有用吗？”，销售可在尚未联系客户时填写：

- 有用、部分有用、暂时无用、尚无法判断，四选一必填；只选程度即可保存。
- 评价时点：阅读后尚未沟通／与客户沟通后。
- 可选原因：研究方向清楚、合作切入点有帮助、PI背景资料有帮助、与负责客户不匹配、缺联系人或触达线索、技术适配不清、资料需更新、重复推荐、其他。
- 可选填写具体原因、希望补充的资料。

销售推荐列表显示最近评价。市场和负责人可在反馈汇总查看有用程度、原因和补充建议；进入单条推荐可回查历史。只允许当前负责销售评价其已分配推荐，归档后仍可补充对推荐资料的看法。其它角色只读，当前角色权限仍是本地演示逻辑。

## 和客户沟通记录分开

推荐评价回答“这份信息有没有帮助”；原沟通反馈继续记录接触情况、客户研究问题、样本/队列、支持需求和下一步。两者独立保存，不能把有用程度直接当成交结果或客户需求。

保存推荐评价不修改跟进状态，不调整PI四维分数、学术角色、热点排名或自动训练模型。本轮也没有执行WorkBuddy补证或评级计划。

## 统计与历史

同一条推荐、同一销售多次修改时保留历次记录。每次保留当时推荐标题、理由、讲题/论文ID、人物ID及来源快照，便于回看评价对象。内容和推荐快照完全相同时重复保存不再新增。

汇总按当前负责销售的最近一次评价，每条推荐只计一次；更换负责销售后，旧销售评价继续保留历史，新销售未评价时显示未评价。未评价和“尚无法判断”分别展示，不算无用。当前展示数量，不合成有用率或成交率。

真实推荐与演示推荐用独立范围切换，默认真实推荐；演示评价始终有标识。未分配草稿不进入统计。历史评价不因取消收藏或普通跟进保存被覆盖。

## 本地数据

沿用localStorage键`clinical-workbench:sales:v1`，保留旧推荐、收藏和客户沟通反馈，版本仍为1，新增可选数组`recommendation_feedback`：

| 字段 | 含义 |
| --- | --- |
| id / recommendation_id | 评价ID、关联推荐稳定ID |
| author_id / created_at | 负责销售、评价时间 |
| value | useful、partly_useful、not_useful、not_assessed |
| stage | before_contact、after_contact |
| reasons / note / needs | 原因枚举、多行说明、希望补充什么 |
| is_demo | 是否演示评价 |
| recommendation_updated_at | 评价时关联推荐的更新时间 |
| recommendation_snapshot | 当时推荐的title、reason、links、expert_keys、origin |

JSON导出自动包含新数组；原`feedback`仍只保存客户沟通历史。数据库与评级文件不变。记录仅当前浏览器，不跨电脑共享，没有真实登录。

## 开发和核验

新模块：`领域工作台/src/recommendation-feedback.js`、`recommendation-feedback.css`；主sales.js接入顶部卡片、列表状态、质量汇总和保存，生成器内嵌为离线HTML。

两张表单分别检测未保存状态：保存推荐评价不重绘客户沟通表单；保存沟通记录时保留另一张未保存的评价草稿。收藏也保留两类反馈。离开未保存表单会提示。

浏览器9项核验通过：必选程度/可选原因、状态独立、不重复保存、版本历史和快照、两表单交叉保存、刷新恢复、离开提示、汇总去重、演示隔离、非负责销售不可写、导出以及手机布局。测试在独立临时浏览器执行，截图中的意见为测试内容，未写入用户浏览器。

核验文件：`页面核验.json`、`保留核验.json`，另有销售卡片及市场汇总截图。原PI库/收藏和人工推荐/跟进流程回归核验保留。本轮未新增采集、未重新评分、未改研究数据库、未发布。

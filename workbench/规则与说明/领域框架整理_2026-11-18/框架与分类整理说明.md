## 本次分工

## 四个入口、一个领域内的两种分析视图

```text
研究领域：糖尿病（其它五领域保留框架）
├─ 领域热点
│  ├─ 研究议题：会议动向 + 论文进展 + 指标线索 + 相关人物
│  └─ Biomarker：具体指标与用途 → 会议提及 / 论文证据 / 转化进度
├─ 会议库：会议层级 → 具体届次 → 会内议题 / 讲者 / 原始报告
├─ 论文库：文章类型与来源 → 原文 / 研究设计 / 结果 / 作者依据
└─ 专家与团队：学术角色 / 讲题 / 论文参与；PI身份独立核实
```

统一入口为领域工作台/index.html，数据中心/index.html也指向它。原会议、论文、Biomarker和报告详情路径保留；各页顶部统一四个主模块，Biomarker不再占顶层导航。

## 分类怎样整理

- 12个研究板块原本已由会议与论文共有，本次保留名称，使用领域中性DM编号做配置层对应，不修改数据库的原ID。
- 58个会议工作议题和51个论文议题整理为66个领域工作议题：43个论文议题按同板块研究问题对应，8个缺少准确会议对应的原议题单列为论文补充议题。
- 这些是框架分类草案，不表示会议和论文在说同一项研究，也不等于议题边界完全相同。映射与理由在框架配置/糖尿病统一议题映射.json，可逐项调整、复核。
- 每条报告/主池论文只进入一个主议题，保留2628条已归类报告、160篇主池论文；618条原文章资料仍可检索。口头默认1256条，海报另筛。
- Biomarker沿其证据对应的报告/论文主议题关联，39个均保留，7常规参照在原专题视图单列。其中3个来自尚未准确分类的目录来源，保留待归类，不硬放邻近话题。

## 页面怎样判断和展示

会议关注及论文进展并列，可分别排序。会议这一栏继续用各会议同类报告占比，国内/国际分别平均后两侧各50%；论文这一栏使用原160篇主池，不把两种数量加成总分。

点击议题，左侧显示会议、论文、指标和公司参与候选入口，右侧显示有角色依据的人物。人物学术角色不加分；2277条来源身份不作为2277个唯一PI，跨来源未自动按姓名合并。论文署名参与、通讯作者和课题PI分开，身份未核者保留待核。

其它五领域有相同四入口空框架，不复用糖尿病数据冒充内容；正式业务范围仍按后续已有资料及业务确认维护。

## 给WorkBuddy的接口

框架配置/研究领域与导航.json定义模块；糖尿病统一议题映射.json定义分类。WorkBuddy资料入库约定.md说明会议、论文、指标与人物分别需要什么来源字段。

WorkBuddy每轮交付原始材料、URL、时间、读取层级、哈希、提取记录、分类建议及待核项。不存在准确主议题时输出pending；新分类由维护侧复核，不强行归并。当前8个会议对应及3个指标分类待办在领域工作台/分类待办.json。采集、正式应用及发布各自按用户具体任务执行，本次没有启动。

## 运行与核验

所有页面为本地静态HTML，JSON内嵌，无需服务器。源码位于各模块src，主入口生成器为脚本/生成领域工作台.py。修改分类配置后重跑主入口生成器即可；修改数据库后先重建各来源导出，再生成领域入口。

```sh
python3 脚本/生成会议视图.py
python3 脚本/生成ADA会议视图.py
python3 脚本/生成会议总入口.py
python3 脚本/生成论文视图.py
python3 脚本/生成标志物视图.py
python3 脚本/生成领域工作台.py
python3 脚本/核验领域框架.py
```

Windows前缀换为py -3 -X utf8，已有Windows工具可提供时区数据。数据库SHA256与改版前相同。备份见变更前基线.json；数据和浏览器核验记录在本目录。

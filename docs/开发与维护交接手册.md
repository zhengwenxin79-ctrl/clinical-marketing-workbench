## 1. 项目全景与业务目标

本项目是面向医药/医疗多组学科研转化领域的**智能营销全链路闭环工作台**，打通了：
```text
学术会议监控 (59个官方锚点)
      │
      ▼
热点追踪与日程抓取 (议题 & 讲者)
      │
      ▼
PI 四维学术评价 (30/25/25/20 标准模型)
      │
      ▼
商机作战卡生成 (破冰话术 / 痛点 / 进院必摸清3件事)
      │
      ▼
一线销售拜访摸底 (在研项目 / 样本队列底数)
      │
      ▼
数据回流市场部 ➔ 自动沉淀入钉钉知识库 (AI 表格)
```

## 3. 两大核心工作台与业务工作流

系统分为两大独立又紧密互通的界面：

### 3.1 市场部主工作台 (`workbench/领域工作台/index.html`)
- **Level 1 (2×2 核心门户)**：
  - **① 热点追踪**：会议热点、学术文献（含 **🌐 综合热点** vs **📅 本周更新** 切换）。
  - **② 作战地图**：6 大疾病领域（糖尿病与代谢、神经精神、呼吸慢病、风湿免疫、心血管、泛血管及器官损伤）专家库与四维评价。
  - **③ 任务派发**：高优商机卡派发到华东、华北、华南战区代表。
  - **④ 业务闭环**：销售拜访反馈回流、样本队列校准专家画像。
- **会议 3 阶段工作流**：
  - `阶段 1：来源与审核`（59 监控锚点 + A/B/C/D 四级评级）
  - `阶段 2：日程分流 & 抓取`（已发布日程提醒抓取议题 ➔ 进一步抓取讲者 PI 进作战地图）
  - `阶段 3：会议热点展示`（自然周热度切片，钻取查看哪些专家在讨论该议题）

### 3.2 销售代表专用工作台 (`workbench/领域工作台/销售工作台.html`)
- **设计风格**：大字号（17px~18px）、大留白（`p-8` 纯白背景）、低噪色块。
- **三大模块**：
  1. `🎯 商机作战卡`：精简客户列表，展示推荐破冰话术（一键复制）、切入痛点、进院必摸清 3 件事清单、四维雷达与卡片评分。
  2. `📍 本战区 PI 库`：本战区专科专家检索、收藏与一键生成作战卡。
  3. `📝 拜访日报`：一线销售填报 **“🔬 目前在研项目/课题基金”** 与 **“🧬 样本队列底数与合作意向”**，并自动同步市场部。
- **数据双向互通机制**：
  通过 `localStorage` 键值实现与主工作台无缝双向互通：
  - `clinical-workbench:battle-cards:v2`：商机作战卡池
  - `clinical-workbench:visit-reports:v2`：拜访日报（含在研项目）
  - `clinical-workbench:intel-list:v2`：一线情报回流池

## 4. 数据底座与核心设计契约

### 4.1 核心数据库不可篡改契约 (Database Invariant)
- **文件路径**：`workbench/数据库/marketing.db`
- **只读原则**：核心学术事实（会议、日程、论文、标志物、历史专家）严禁直接写入非受控数据。
- **校验基线**：
  ```text
  SHA256: 645adc48a9af2eb67a9df04a0f4990fce706a5a4fcf2fe467c8e2372f0e78568
  ```
  构建与回归脚本每次执行都会校验该 Hash，如果不一致将立刻中断并报错，防止脏数据污染学术事实。

### 4.2 PI 四维学术评价模型 (clinical-research-v3 口径)
所有专家的综合分均严格按照四维百分制计算，**“缺证不填，有证才给，严禁凭空估分”**：
1. **研究方向契合度 (30分)**：多组学、标志物、疾病队列直接关联度。
2. **学术产出质量 (25分)**：近 3 年第一/通讯作者高分 SCI、指南共识牵头。
3. **科研转化潜力 (25分)**：在研国自然/重大专项、临床样本库冻存规模与随访终点。
4. **平台资源禀赋 (20分)**：国家医学中心、重点实验室、学会主委/副主委任职。

等级划分：**A级 (≥90分)** / **B级 (75~89分)** / **C级 (60~74分)** / **D级 (<60分)**。

## 5. 钉钉与 WorkBuddy 自动化数据流水线

### 5.1 WorkBuddy 信箱工单机制 (Mailbox IPC) 与专属 Skill 规范

为了解决纯 Web 端受浏览器沙箱限制、以及大模型输入自由提示词易格式漂移的缺陷，本项目落地了工业级 **信箱工单机制 (Mailbox IPC)**：
- **信箱目录**：
  - `workbench/agent_mailbox/inbox/task.json`：存放前端派发的结构化抓取工单；
  - `workbench/agent_mailbox/outbox/progress.json`：存放 Agent 执行过程中的打字机进度日志；
  - `workbench/agent_mailbox/outbox/latest_result.json`：存放抓取与清洗完成后的产物。

### 5.2 专属 Skill 安装与通用寻址指引 (试用前必读)

本项目深度绑定吉因加医学部定制的 **《会议收集与评级》专业技能**（含 6 大慢病子方向、销售 10 覆盖城市硬性规则、排除纯线上/技术会等防幻觉定级标准）。

为保证**“任何人、在任何电脑上克隆或解压本项目都能开箱即用”**，系统支持通用双路径自动寻址：

| 模式 | Skill 安装/存放位置 (克隆规范) | 适用场景 | 说明 |
| :--- | :--- | :--- | :--- |
| **🥇 D盘统一通用规范 (推荐)** | `D:\Users\skills\conference-collection-rating\SKILL.md` | 所有开发与生产测试环境统一标准 | **已在 D:\Users\ 建立通用克隆副本**，路径全局固定，中继服务优先自适应加载。 |
| **🥈 项目内部备份副本** | `clinical-marketing-antigravity-20261119/skills/conference-collection-rating/SKILL.md` | 离线演示 / 独立分发 | 仓库自带完整规范，杜绝环境缺失。 |
| **🥉 本机历史自定义路径** | `C:\Users\...\WorkBuddy\...\_input\会议收集评级\SKILL.md` | 原生会话调试 | 中继自动向下兼容兜底。 |

#### 新人试用操作步骤 (Runbook)：
1. 启动本地信箱中继服务：
   ```bash
   python tools/workbuddy_mailbox_bridge.py
   ```
2. 打开工作台 `workbench/领域工作台/index.html`，进入 **「来源与审核」➔「⚡ 一键抓取」**；
3. 点击 **「🚀 立即启动 WorkBuddy 抓取」**：
   - 系统自动生成并写入 `workbench/agent_mailbox/inbox/task.json`；
   - 自动复制执行指令到剪贴板；
4. 点击 **「🔗 唤醒 WorkBuddy 客户端」**，在聊天窗口粘贴指令发送，Agent 即可严格按照标准 Skill 规范开始深度全网采集，并在网页端实时刷新进度流！

## 5.3 钉钉多维表格与周增量数据流水线

系统内置针对 **钉钉知识库（AI 表格）** 的标准化输出流水线，支持 WorkBuddy 自动化搬运：

### 5.1 数据接口定义
每次执行 `export_pages.py`，系统会在 `dist/dingtalk/` 自动生成：
- **`dingtalk_full_baseline.csv / .json`**：
  - **用途**：首次建库全量基线。
  - **URL**：`https://zhengwenxin79-ctrl.github.io/clinical-marketing-workbench/dingtalk/dingtalk_full_baseline.csv`
- **`dingtalk_weekly_delta.csv / .json`**：
  - **用途**：每周一增量更新（由系统算法去重后输出）。
  - **URL**：`https://zhengwenxin79-ctrl.github.io/clinical-marketing-workbench/dingtalk/dingtalk_weekly_delta.csv`

### 5.2 WorkBuddy 任务设定
1. **首次初始化任务**：
   从 `dingtalk_full_baseline.csv` 读取，一次性导入钉钉知识库《临床科研智能营销数据库（AI 表格）》。
2. **每周一增量定时任务**：
   每周一早 09:00 读取 `dingtalk_weekly_delta.csv`，**直接追加到表格末尾（无需 Agent 去重）**。

## 6. 日常开发、构建与发版运维 (Runbook)

接手同事在日常开发时，只需掌握以下三条命令：

### 6.1 本地重新编译构建
当修改了 `workbench/领域工作台/src/` 中的任何 HTML/JS/CSS，或需要更新快照时：
```powershell
Set-Location "d:\Users\智能营销_Antigravity开发交接包_20261119\clinical-marketing-antigravity-20261119"
python -X utf8 tools/export_pages.py
```
> 执行该命令会自动：重新提取 SQLite ➔ 注入模板 ➔ 生成 `index.html` 与 `销售工作台.html` ➔ 输出静态资源到 `dist/` ➔ 输出钉钉全量与增量包。

### 6.2 运行回归测试
在提交代码前，**必须 100% 通过 5 项自动化回归**：
```powershell
python -X utf8 workbench/脚本/核验领域框架.py
python -X utf8 tools/test_regression.py
```
测试项包括：
- [1/5] 66 张数据表、25 视图、66 议题及标志物守恒检查
- [2/5] 周更新自然周（周一至周日）切片与边界算法
- [3/5] 市场 vs 销售 RBAC 角色权限与战区范围隔离
- [4/5] PI 四维评分（30/25/25/20）与分级逻辑
- [5/5] 收藏夹与拜访反馈跨端隔离与防污染测试

### 6.3 部署推送到线上 GitHub Pages
测试通过后，提交并推送到 GitHub 即可自动触发 Pages 发布：
```powershell
git add -A
git commit -m "feat: 你的改动描述"
git push origin main
```
线上访问地址（约 30~60 秒生效）：
- **市场主台**：`https://zhengwenxin79-ctrl.github.io/clinical-marketing-workbench/`

## 7. 常见二次开发场景与操作指引

### 场景 A：我想调整销售工作台的界面排版或话术展示
1. 打开 `workbench/领域工作台/src/sales-portal.html`；
2. 修改其中的 Tailwind CSS 类名或 Alpine.js 绑定逻辑；
3. 运行 `python -X utf8 tools/export_pages.py` 重新生成。

### 场景 B：我想修改或增加商机作战卡
1. 打开 `workbench/领域工作台/src/sales-portal.html`，定位到 `DEFAULT_BATTLE_CARDS` 常量；
2. 同时打开 `tools/export_dingtalk.py`，在 `CURATED` 字典中同步增加该专家的在研项目和痛点；
3. 重新构建并推送到 GitHub，钉钉同步包也会同步生成。

### 场景 C：未来有公司独立服务器，如何脱离 GitHub 迁移？
1. **前端静态资源**：直接将 `dist/` 目录拷贝到 Nginx / Apache 静态服务器目录即可；
2. **后端 API 网关**：可基于 `tools/auth_server.py` 扩展为正式 FastAPI / Go 服务，对接公司 LDAP / 钉钉企业免登；
3. **数据同步**：将 WorkBuddy 拉取 CSV 的 URL 改为公司内网域名（例如 `https://marketing.yourcompany.com/dingtalk/dingtalk_weekly_delta.csv`），钉钉端无需任何修改！

# 临床科研营销智能体框架方案

> **核心目标：帮助市场发现值得投入的研究机会，帮助销售找到合适的临床科研客户，并通过真实反馈持续修正判断。**
>
> **当前重点：搭起整体框架，优先建设热点洞察，接上已有会议和 PI 调研。** 每周清单持续交付，销售反馈和效果分析随后完善。

**承载与推进方式**：先搭建“临床科研市场情报台”，整体初版页面设计见第六节；**当前糖尿病会议洞察的下一阶段任务见第七节**，优先推进工作台框架与每周会议提示、热点量化排序、国际会议资料可获取性测试。页面方案属于整体营销智能体的分阶段实现，延续下述三个业务模块。

## 一、业务定位：围绕临床问题，寻找科研合作机会

这条业务线从**尚未解决的临床问题**出发，匹配组学和分析技术，帮助临床团队开展有转化前景的 **Biomarker 发现研究**。

当前重点是标志物筛选，靶点发现与验证是延伸方向。单细胞、cfRNA、cfDNA 甲基化、虚拟细胞等，是参与研究的技术工具。

筛选信息始终围绕四个问题：

1. 具体疾病还有什么诊断、监测、预后或分层问题没有解决？
2. 新进展是否带来了值得研究的机会？
3. 公司能力能参与哪一环？
4. 哪些临床团队正在研究这些问题？

优先关注本业务线选定领域中有临床转化前景的问题。非常基础、缺少临床问题连接的机制研究，优先级较低；肿瘤和感染常规业务涉及其他团队分工，当前不作为主要投入方向。

[[wenxin/实习实践/吉因加临床科研能力表|公司能力表]]用于查能力、来源和证据边界；还需结合**本业务线当前重点**筛选，不能把公司全部产品直接当成营销重点。六大领域的准确范围及重点病种，需与 Mentor 对齐。

## 二、整体框架：三个业务模块，共用知识库

**热点与研究问题 → 会议和 PI 机会 → 销售行动 → 真实反馈 → 修正方向与客户画像**

这条主线同时接受已有会议清单和客户资料作为入口，不要求每次都从热点开始。

| 模块 | 回答什么问题 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| **1．热点洞察** | 什么值得关注，为什么与我们有关？ | 国内外会议成果、前沿文献与临床进展、公司产品更新、基金与政策信息 | 候选热点、初步价值判断、宣传选题与方向观察线索 |
| **2．客户与会议机会** | 找谁、在哪里找、怎么准备？ | 热点与研究问题、会议日程、已有客户池、PI公开研究资料、公司能力 | 推荐会议、重点PI、匹配理由、沟通切入点和待确认信息 |
| **3．销售反馈与效果** | 之前的判断是否准确，下一步如何调整？ | 销售实际沟通、客户反馈、后续跟进与意向记录 | 客户画像更新、跟进状态、对热点和推荐规则的修正建议 |

三个模块是本方案建议的组织方式，具体命名和展示层级供 Mentor 审阅。

### 模块1：热点洞察——先找到进展，再判断用途

“某场会议即将召开”属于会议信息；热点洞察还需要提取**研究成果、结论和具体问题**。

每条进展初期只需讲清：

> 什么疾病或问题 → 有什么新进展 → 用了什么技术 → 与公司哪项能力有关 → 建议如何使用。

信息来源分为四类：

- **国内外重要会议**：新研究结果、新治疗或检测手段。
- **前沿文献与临床进展**：研究问题、技术、主要结论及证据局限，不只看期刊级别。
- **公司产品与技术更新**：新增能力、方案和版本变化，用于维护能力资料。
- **基金、政策与申报通知**：投入方向、申报启动和时间窗口，先提供提示，复杂客户匹配后续再做。

热点保留两种用途：**近期营销可用**，用于宣传选题或销售交流；**方向观察**，提示未来研究与布局。候选热点池与本周推广选题分别保留，初期不要求每条都做成论文精读。

### 模块2：客户与会议机会——把信息变成销售可用的建议

两条路径并行：

- **从热点出发**：确定具体疾病与问题，再找相关团队、PI和会议。
- **从会议出发**：从重要会议的日程与讲者中发现客户和研究问题，再联系热点及公司能力。

会议分层处理：

- **全国性重要大会**：提前跟踪，优先获取日程与重点PI；包含手术内容不应导致整场排除。
- **销售所在区域的会议**：提供简明判断，方便销售按时间和客户机会选择。
- **相关性较低的会议**：可以保留信息、降低优先级，不必全部深调。

PI判断关注具体研究方向、科研活跃度、经费线索、想法和新技术兴趣。讨论中的“三有青年”作为客户画像线索，先用实际案例校准，不直接变成年龄门槛或固定评分公式。

**给销售的交付必须能直接使用：推荐会议、重点人员、为什么相关、可以讨论什么、还有什么待确认。** 每周清单尽早交付，重要大会提前准备。

### 模块3：销售反馈与效果——用实际沟通修正公开调研

反馈重点记录：实际接触了谁、客户关心什么问题、研究方向和资源有何变化、是否有合作意向，以及下一步安排。

这里的“客户建模”首先是**持续更新客户画像**。公开调研和真实沟通分别留来源，帮助修正过时信息及不准确的匹配判断。

当前先在框架中预留反馈位置。随后用少量真实记录验证更新是否准确，再补触达与意向转化统计。效果分析应结合实际跟进、销售资源和项目周期，不能由一次未成交直接推断热点没有价值。

## 三、任务优先级：当前做什么，后续补什么

| 顺序 | 任务 | 要形成的结果 |
| --- | --- | --- |
| **当前主要任务** | 搭建整体框架，明确模块关系与分层 | 可以和 Mentor 逐项讨论的方案与工作台框架 |
| **当前重点建设** | 建立热点发现与初步判断，接上会议和PI信息 | 能说明“新进展是什么、为什么值得关注、与我们有什么关系” |
| **持续交付** | 每周会议清单、重点会议PI清单 | 销售可直接选择会议和接触对象，重要大会提前准备 |
| **必要支撑** | 确定知识库位置，整理能力和研究资料 | 信息可以稳定保存、检索、复用，并有适当权限 |
| **随后建设** | 回收销售反馈，更新客户画像 | 将公开调研与真实沟通关联起来 |
| **可以后置** | 深度科研工具联动、自动更新准确性验证、完整转化统计 | 逐步完善闭环，不阻塞前面模块使用 |

先用真实样例明确判断标准，再逐步自动化；保留人工复核与“继续观察”的空间。

1. **整体框架**：三个业务模块，共用知识库、公司能力资料和人工复核位置。

**第一版先把已有信息连接起来、让业务逻辑看得清楚；反馈模块预留位置，随后逐步补齐数据和自动化。**

## 六、初版建设方案：临床科研市场情报台

**2026-11-12补充，用户已确认本节框架方向。** 初版帮助市场部回答：**发生了什么、为什么值得关注、与我们有什么关系、下一步可以做什么。** 先完成情报组织、初步判断与呈现，客户跟进、销售反馈和效果分析预留连接位置。

### 1．五个业务页面，两个公共入口

```text
临床科研市场情报台
├─ 情报总览
├─ 领域热点
├─ 会议与团队
├─ 产品与技术
├─ 基金与政策
└─ 公共入口：信息源｜判断标准
```

| 页面 | 核心用途 | 初版展示内容 |
| --- | --- | --- |
| **情报总览** | 快速掌握近期值得注意的变化 | 本周重点进展、正在追踪的研究问题、近期会议与申报窗口、待核信息 |
| **领域热点** | 判断各领域正在研究什么 | 按领域、疾病和具体问题查看主题、代表研究、研究用途与证据状态 |
| **会议与团队** | 了解会议内容及相关研究者 | 会议日历、议题与结果、讲者／团队、研究方向及值得进一步了解的问题 |
| **产品与技术** | 从公司能力寻找研究应用 | 按cfRNA、甲基化、单细胞等技术查看应用进展、研究设计与能力适配 |
| **基金与政策** | 发现研究启动和投入窗口 | 申报方向、时间节点、相关研究主题及可进一步了解的团队；复杂客户匹配随后补充 |
| **信息源** | 管理去哪里获取资料 | 会议、期刊、公司资料等来源目录，以及实际采集状态、覆盖范围和缺口 |
| **判断标准** | 解释分类和推荐依据 | 文章相关性、热点判断、公司适配及人工复核口径 |

五个页面属于呈现与使用入口。整体业务仍按“热点洞察—客户与会议机会—销售反馈与效果”组织，知识库提供共用支撑。

### 2．首页先呈现判断与行动窗口

首页按以下顺序组织，市场人员先看到重点，再进入具体证据：

1. **本周值得关注**：精选少量进展，说明发生了什么、为什么值得看。
2. **正在追踪的研究问题**：呈现具体主题及本周新增证据。
3. **近期机会窗口**：即将召开的会议、申报节点及需要提前准备的事项。
4. **待补与待核**：列出需要确认的原始结果、技术细节和能力适配问题。

初版由人工选择和复核重点，逐步积累可复用的判断依据。

### 3．共用情报记录，通过不同视角查看

一项研究可以同时归入领域、会议、技术和团队。例如，一项ADA的EV蛋白研究，可以从“糖尿病—T1D部分缓解”“ADA”“蛋白组”三个入口打开同一条研究详情。后续取得正式论文时，关联同研究版本并统一更新。

研究记录采用固定结构：

> **研究问题 → 团队与来源 → 方法与发现 → 研究用途 → 技术关联 → 当前状态 → 下一步。**

“下一步”可以是补原文、追踪验证、确认公司适配、了解团队或考虑宣传选题。初版记录建议及其依据，后续再连接具体负责人、跟进和反馈。

领域热点页分为两层：**主题地图**围绕具体问题组织代表研究和判断；**最新动态**按时间展示新论文、会议结果与技术进展，并关联到主题。既有糖尿病试点中的研究、来源与标准可复用，会议发现和技术发现继续作为进入问题的两条路径。

### 4．初版建设顺序与验收

1. 搭出五个业务页面和两个公共入口的结构。
2. 统一情报卡片、研究详情和主题卡字段。
3. 接入已有糖尿病资料，验证跨页面关联与版本更新。
4. 人工选择重点，形成第一期情报总览。
5. 跑通后逐步扩展领域和持续采集，再连接客户机会与反馈。

**初版验收标准：从首页的一条重点情报出发，可以追溯研究问题、原始证据、技术用途、相关团队及下一步建议。** 来源覆盖与证据状态明确；具体研究只有一份核心记录，各入口引用一致。

执行口径复用[[wenxin/糖尿病热点知识地图/14 文章相关性与热点判断标准|文章相关性与热点判断标准]]；已有试点见[[wenxin/糖尿病热点知识地图/00 项目主页|糖尿病热点知识地图]]。本节网页框架已于2026-11-12按用户要求接入现有工作台：五个业务页面、两个公共入口、问题主题及计划讲者详情已可查看。复用已有糖尿病资料；基金通知和真实客户反馈待接入，本次未启动新采集。

**阶段目标**：从国内外会议与文献切入，让工作台能够发现近期会议、排列重点议题，并说明研究进展、依据及资料缺口。

### 1．工作台框架与每周会议监控提示

**页面组织**：首页突出本周会议卡片，下设“国际会议、国内会议、文献热点”三个平级入口。国际、国内会议均归属会议热点洞察业务，文献热点归属论文热点洞察业务。进入会议后按临床问题、研究用途和相关方向下钻；Biomarker页面与产品技术入口保留，具体产品契合度随后结合真实产品优化。

**采集方式**：固定会议源为主，泛搜索补充。糖尿病先围绕ADA、EASD、CDS等建立监控清单，具体届次与日期在实际采集时核实；风湿免疫等其他领域的会议归入对应领域。

**监控流程**：每周自动检查会议名单与新增线索 → 核对日期和官方入口 → 按会议及届次去重 → 更新首页卡片 → 进入会议资料和热点提取。执行环境与具体运行时点在实现时配置，保留手动刷新入口。

首页分别提示本周即将召开、正在举行，以及近七日刚结束的会议。按Asia/Shanghai界定本周，保存会议当地日期及时区依据；日期不明时标待核。每张卡片至少显示会议名称、领域、起止日期、地点/形式、状态、资料获取情况、来源链接及最近检查时间。一次扫描失败保留上次结果并提示本次状态。

**交付与完成标准**：形成可点击的首页及三个入口、核心会议源清单和每周更新流程；能从会议卡片进入具体会议，回查日期依据，辨认新发现或有资料更新的会议。会议发现、日程获取和成果提取分别标记状态。

### 2．热点以量化排序为主，词云作为辅助

会议详情优先展示重点议题榜单，词云保留作探索和PPT展示。每条议题显示排名、主要进展、分项指标、评分理由、证据状态和原始来源。

### 4．数据库对象和关系

先明确六类业务对象；实际物理表和关联表在字段/关系设计时确定。

1. **来源与原始材料**：会议官网、日程、摘要、论文、取得时间及覆盖范围。
2. **报告与论文记录**：每条来源内容的稳定身份、原文事实与读取状态；会议报告与论文类型分开。
3. **研究身份与版本关系**：报告/论文可关联同一研究；关系区分确定同源、共享队列、疑似重叠、待核。研究归属不明时留空或待核，不强行生成独立研究结论，不删除原始材料。

5. **人员与团队**：人物身份、机构、此次会议任务、研究关联与学术角色依据。
6. **公司能力**：技术/产品ID、确认范围、依据版本与日期、交付条件及缺口。

会议系列/届次、专题和报告之间有从属关系；报告、人员、材料及研究之间允许多对多关联。**一条报告不自动等于一项独立研究；一个报告对应多个指标时，保留各自用途关系。**

主题归类、关注判断、转化优先级、产品匹配和未来评分作为分析结果保存，携带规则版本、判断依据和复核状态。事实/来源与判断分开维护，页面读取统一查询结果。

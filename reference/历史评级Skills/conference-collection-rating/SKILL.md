# 会议收集与初评

目标：尽量找全相关会议，再判断哪些值得市场部进一步取日程、了解临床科研PI和研究团队。交付可追溯的会议清单，并说明检索缺口。不承诺互联网会议已全部收齐。

## 业务口径

- 默认六大领域：自免、内分泌、神经精神、心血管、慢阻肺、泛血管。它们是分类，不是搜索词全集；用 [registry.json](references/registry.json) 的子方向扩展发现。
- 默认销售覆盖北京、上海、杭州、苏州、南京、长沙、广州、深圳、成都、重庆。全国核心会不限举办地；其他地区先发现再判断，不在检索阶段过滤。录音中提及的徐州等潜在例外，写明区域待人工确认，不直接扩大覆盖范围。
- 优先了解“临床问题＋科研＋转化”、与检测或分子标志物研究相关的会议，不要求先准备完整产品库。纯病例普及、操作培训、心理科普、纯影像AI等通常较低相关；结合真实内容，不按科室、关键词或机构名字一刀切，影像结合分子检测研究等仍可相关。当前骨质疏松等非重点方向保留筛选理由和人工例外。
- 全国性专业组织的相关正式专科年会优先追踪。不能仅因日程、PI名单或人数缺失降级；也不能只凭全国组织、AI或临床字样推断科研合作价值。已有明确低相关内容证据时，说明理由后降低推荐。
- 默认国内举办的会议，含在国内举办的国际冠名会议；国外会议仅在用户指定范围时扩展。不改动后续客户评级标准，不查询每位PI的论文、基金或采购意愿。

## 先准备本轮覆盖清单

沿用用户明确的日期。未指定时按北京时间下一自然周周一至周日，先写出日期；同时发现未来6周线索，未到目标周的进入储备，不丢弃。新建本轮台账：

```bash
python3 scripts/conference_run.py init --start YYYY-MM-DD --end YYYY-MM-DD --output run.json
```

可用 `--previous 上轮run.json` 带回会议储备与人工意见。脚本只生成检索任务和检查台账，实际检索由当前环境可用的搜索、浏览、PDF/OCR工具执行；不假装已安装其他 Skill。

执行前阅读 [采集与证据规范](references/method.md)。入口、名称别名和核心会议系列见 [registry.json](references/registry.json)。入口会变，失效时找替代路径并登记，不把单次502判成永久停用。

## 五步工作流

### 1. 广泛发现，先建候选池

- 逐项执行台账里的任务：中华医学会×六领域、中国医师协会×六领域分别检查；再查其他全国专题组织、覆盖区域的医学会与医师协会、会务平台和开放检索。
- **规范名称：中国医师协会（CMDA），不是“中华医师学会”。** 错称可辅助找旧线索，不能代替正确名称检索。
- 每个核心系列登记当年去向：已找到本届、尚未找到、资料受限、已取消等。查完医学会不等于查完医师协会，查过平台首页不等于查完目录。
- 查年度计划的全部相关章节，包括二类会议、图片页、月份待定项；候选日期不在本周或只有旧届信息，也登记后追查本届。搜索同时用年份、年会/医师大会/专题会议、疾病子方向和品牌简称，不只搜索“日期＋六大类”。
- 平台分页、动态列表、独立大会域名、公众号和PDF入口都需说明实际读取范围。零结果、访问失败与未检索分开记录。先保存会议名称和发现出处，再核实或评级，不因资料不齐删除线索。
- 读取目录或计划表时先保留源条目清单及其实际条目数，每条会议条目连接候选编号；非会议条目注明原因。不能只保留最终入选项，让已看到但误筛的会议无迹可查。

### 2. 逐字段核实本届安排

- 追到本届正式通知、大会官网或可确认受主办方维护的会务页，分别核实身份、主会日期、城市、日程。按发布者、字段和版本采信，不按域名整体判真。
- 年度计划、继教申报、采购需求、资助和参展排期都可补线索，但不单独冒充最终会期；多个转载也不是多个独立来源。最新有效更正优先，无法解决冲突则保留两版并标待核实。
- 分别记录主会、会前会、直播和Workshop日期。周清单默认按主会与目标周是否重叠纳入；相关附属活动可单列说明，不延长整场会期。
- 只有计划时间不能写成已举办；日期已过而缺实际举办证据，写“计划日期已过，举办状态待核实”。本届人数区分预计、报名和实际，未知不估算。
- 核心日期未知或冲突时保留待核实；确认改期出本周的进入储备或排除记录，不能继续出现在本周已确认清单。

### 3. 去重并保留更新历史

按“会议系列＋届次/年份＋主办身份”识别同届会议，日期和城市变动不创建另一场。多个来源合并；同期不同会议及分会场关系分别记录。模糊相似仅提示人工确认，不自动误合并。

保留每条候选的去向：本周已确认、本周待核实、储备、低相关/其他排除、重复合并。保留旧值、更新证据和人工意见；未经核实不覆盖人工结论。

### 4. 简单初评并给出下一步

不打百分制。主办级别和规模作为线索，最终结合内容和区域判断：

| 等级 | 判断与动作 |
|---|---|
| 重点关注 | 业务相关的正式全国性学会/分会年会，或有明确相关研究团队、临床科研专题的高价值会议；优先取日程，注明重点专题。未出日程时保留重点并写待补 |
| 常规关注 | 有相关价值的覆盖区域会议或可参与的线上会议；供属地BD选择性查看，不强制深拆所有讲者 |
| 低优先级 | 证据显示以低相关内容为主，或非覆盖区域普通会议；记录理由，避免下一轮重复花精力 |
| 待确认 | 正式身份或内容不足以判定价值；明确待核实问题。已确认相关核心年会仅缺日程/名单时不用此类 |

在备注中把“关注价值”和“资料是否齐全”分开写。可建议“补查官方通知/取相关分会场日程/属地查看/暂不深拆”，不直接给销售编造具体客户需求或话术。

### 5. 反查查漏，再交付

- 用组织/系列底表反查候选池，追问“这个分会本届在哪里？”；用开放检索找未在底表里的新品牌会，不能只验证已收录会议。
- 每条候选有去向，每个未完成来源有缺口及下一步。核心系列未找到、图片页未读、关键入口受限时，交付应说明部分覆盖，不写“候选池闭合/全部无遗漏”。
- 执行 `python3 scripts/conference_run.py audit run.json --output audit.json`。修复结构和规则错误；无法补齐的访问缺口据实交付，不填造假日志让检查通过。脚本校验台账一致性，不证明网页内容真实或全国会议已找全。
- 保留原12列：`序号｜领域大类｜疾病方向｜会议名称｜会议时间｜会议地点｜会期｜参会人数｜联系人｜状态｜优先级｜备注`。主清单给本周已确认会；待核实会单独分组但沿用同一表头，储备和排除留台账。备注给理由、来源、重点专题及待补事项。
- 交付简短说明：各类会议数量、覆盖任务完成情况、未完成来源、核心会去向、值得人工核对的边界案例。输出本轮 `run.json` 和 `audit.json` 供续跑。可导出Excel；无表格能力时提供CSV并说明限制。

## 节奏与审核

周四/周五先出下一周概览，周一9点前经辛小青审核后交BD；日程待出项建议1—2天后复查。没有调度能力只列复查事项，不声称自动监控。不自动推送、联系人员、报名或改客户评分。没有核心新会议时，不为凑数生成推荐。

版本：v1.0，收集与初评整合版。适用于替代“抓取后再单独初评”的串联用法；历史旧文件作为参考，运行以本包为准。

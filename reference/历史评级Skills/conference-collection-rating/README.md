# 营销智能体会议收集与初评

面向吉因加临床科研业务，先广泛发现会议，再筛选值得了解临床科研PI和研究团队的场合。每周交付仍是熟悉的12列会议表，后台增加可续跑的来源与候选台账。

## 解决什么问题

原流程会列很多网站，但无法知道哪些组织、分会和会议系列没有查到；补到一个网站也无法证明不再漏会。这个版本增加四个机制：

1. **先列检查范围：**中华医学会和中国医师协会分别检查六大领域，扩展其他专题组织、区域组织和独立会务站。
2. **每条线索有去向：**已确认、待核实、改期储备、低相关和重复合并都有记录，信息不足不会静默消失。
3. **按字段核实最新版本：**正式通知优先；计划、采购或参展排期可提示变化，不能直接替代最终安排。
4. **用底表反查遗漏：**核心系列、上轮储备、未读PDF页、失败入口都要交代，并用检查脚本指出缺口。

## 怎样评级

只用“重点关注／常规关注／低优先级／待确认”，附简短理由和下一步。相关正式全国性年会优先关注，缺日程或PI名单不自动降级；已经明确低相关的内容仍需筛选。

结合讨论录音，关注临床问题、科研和转化。规模大、名字有AI或属于临床学科都不足以单独推荐；综合大会可只关注相关分会场。会议初评不改后续客户评分，不逐人深查基金或论文。

## 怎么用

把整个文件夹提供给WorkBuddy等支持本地Skill的工具，保留目录结构。新任务中可直接发：

> 请使用 conference-collection-rating 收集指定周的会议。先生成覆盖清单，独立检查中华医学会与中国医师协会及核心会议系列，再核实本届最新安排。按临床科研交流价值初评，输出12列会议表、待核实项和来源缺口；保留run.json并运行audit。不要推送。

脚本仅需Python 3.9及以上，无额外依赖：

```bash
python3 scripts/conference_run.py init --start 2026-11-02 --end 2026-11-08 --as-of 2026-11-05 --output run.json
python3 scripts/conference_run.py audit run.json --output audit.json
```

上面的日期仅为对照测试窗口，实际使用替换为需要的周。`init --previous 上轮run.json` 可带回储备和人工意见；实际检索仍由AI及其搜索、浏览、PDF/OCR工具完成，脚本不会自动联网采会。

## 文件

- [SKILL.md](SKILL.md)：日常执行入口。
- [references/method.md](references/method.md)：来源采信、去重、台账填写和查漏办法。
- [references/registry.json](references/registry.json)：领域、组织名称、入口和核心系列种子；可逐步补充，不是完整行业名录。
- [scripts/conference_run.py](scripts/conference_run.py)：生成覆盖任务、检查台账。
- [tests/test_conference_run.py](tests/test_conference_run.py)：离线场景验证，测试数据均为假设。

## 如何确认有改善

用同一时间窗口和同一业务口径对比旧结果；另准备mentor已知的重要会议作独立核对，不只检查AI已收录的会议。分别统计“没发现”“发现后误筛”“日期核实错误”，将漏会补成组织/系列线索，避免只增加一次性的会议名称。

来源任务完成率衡量执行范围；已知会议找回率只衡量已知核对集，两者都不等于全国真实会议召回率。验收通过表示台账可供审核，不表示互联网会议全部收齐。任何渠道受限可交部分结果，但必须报告缺口。

v1.0。已承接原初评的全国性年会优先规则，加入会议收集与查漏机制。默认国内会议；销售覆盖仍按既定10城，其他区域核心会议可保留。输出须经辛小青审核后进入推送环节。

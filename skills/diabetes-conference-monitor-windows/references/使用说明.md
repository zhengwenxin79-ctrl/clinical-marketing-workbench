# WorkBuddy 导入与使用说明

这个包把现有“会议采集→变化比对→待复核网页”封装为一个可调用技能。包内有Skill说明、来源范围、采集逻辑和校验入口；已有研究台继续保存在原项目中，无需把整个Obsidian知识库上传到技能市场。

## 1. 导入

在WorkBuddy打开“专家·技能·连接器 → 技能 → 添加技能 → 上传技能”，选择交付的 `diabetes-conference-monitor-windows.zip`。解压后应为单层同名技能目录，内部直接包含 `SKILL.md`、`scripts/` 和 `references/`。导入后在“已安装”确认“糖尿病会议采集与复核（Windows版）”已启用。

依据：[WorkBuddy技能上传说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)、[技能包结构规范](https://open.workbuddy.cn/docs/skill)。本包按WorkBuddy字段编写，未在用户客户端中实际点击导入；若导入器提示错误，保留报错供核对，不改成仅复制提示词。

## 2. 选择Windows本地项目

解压完整迁移包后，把WorkBuddy工作空间选为其中的 `workbench` 文件夹，例如：

```text
D:\clinical-research-windows\workbench
```

在任务中主动选中Windows版技能。技能目录与项目目录不同；采集核心随Skill打包，项目提供研究数据、网页模板和观察基线。详细步骤见 [Windows使用说明.md](Windows使用说明.md)。

## 3. 先检查，再单次运行

先复制 [任务提示词.md](任务提示词.md) 的“仅检查环境”。此模式检查文件、Python/curl、来源配置与打包完整性，不联网、不生成新草稿。

确认检查通过且要采集时，再使用“单次采集”。任务执行后应返回一个真实运行编号、来源数、失败项和可打开的待复核网页。部分成功仍会输出草稿，但应标明缺口。

环境：Windows 10/11、Python 3.9及以上、curl.exe；macOS/Linux使用python3与curl。入口及核心逻辑只用Python标准库，不自动安装依赖。本版已做跨平台适配及离线验证，尚未在Windows实机中运行。

## 4. 到哪里看结果

工作台项目内：

- `monitoring/待复核/index.html`：最新草稿；打开后切换“本周新增／更新”。
- `monitoring/runs/运行ID/复核报告.md`：该轮全部来源状态及缺口。
- 同一运行目录的 `fetch-report.json`、`observations.json`、`weekly-meetings.proposed.json`、`manifest.json`：响应、提取、变化及校验记录。
- `skill-execution.json`：通过本Skill入口执行时保存的实际结果；只做verify模式不另写结果文件。

正式首页保留原版本。首轮已有数据记录CDS日程页内容待核、CSE请求超时；本包不声称已经解决这两个来源缺口。维护后的来源或项目构建脚本与此版本不一致时，入口会要求更新并重新验证Skill。

## 5. 退出码和问题处理

- `0`：环境或产物检查通过；采集可能为完整或部分成功，仍需看 `run_status`。
- `2`：环境、来源配置、包文件或证据验收失败；停止使用该轮结果并报告原因。
- `3`：产物结构可验证，但所有来源都未成功解析；按采集失败报告，历史会议保留。

客户端无Python、无curl或项目权限不足时，报告缺项。来源改版造成解析缺口时，不让模型自行编造替代记录。首次发现日期是系统观察日期，不能当主办方发布日期。

## 6. 维护边界

本包不带定时器，不会恢复原先暂停的Codex任务，也没有正式应用脚本。文件哈希校验用于检测流程内意外修改；实际文件写入权限仍由WorkBuddy和操作系统决定，Skill文本不能代替权限隔离。

核心文件基于现有采集逻辑，适配UTF-8、目录锁、UTC+8及curl.exe；原逻辑与适配文件哈希记录在 `package-manifest.json`。升级流程应核对源码、更新包与离线验证，不在运行中自动改规则。

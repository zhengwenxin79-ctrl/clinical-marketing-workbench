# 可复制的WorkBuddy任务提示词

以下D盘路径是示例，请换成解压后的实际workbench目录。Windows调用Python使用 `py -3 -X utf8` 或 `python -X utf8`。

先在WorkBuddy任务中选中“糖尿病会议采集与复核（Windows版）”技能，并指定已有工作台文件夹。下面两种任务分别发送；第一种不会抓取。

## 仅检查环境（首次使用）

```text
使用“糖尿病会议采集与复核（Windows版）”（diabetes-conference-monitor-windows）技能。
项目目录为：D:\clinical-research-windows\workbench

读取该技能的SKILL.md，确定真实安装目录，调用scripts/run.py的--mode check，项目根目录通过--project-root传入。
本次只检查运行环境和项目兼容性，不联网采集，不修改项目，不创建或恢复定时任务。
依据脚本实际输出，告诉我是否可以执行以及具体缺项；不要把“已读取技能”当作执行成功。
```

## 单次采集（准备好后使用）

```text
使用“糖尿病会议采集与复核（Windows版）”（diabetes-conference-monitor-windows）技能。
项目目录为：D:\clinical-research-windows\workbench

先读取SKILL.md并运行scripts/run.py的--mode check；通过后以--mode collect执行一次。
保持打包的8个会议入口、解析代码及项目正式文件原样，只生成待复核结果。
不得调用promote.py，不设置或恢复任何定时任务，不对外发送或发布。
执行后依据真实日志汇报：运行编号、完整/部分/失败、成功来源数/总数、本轮新候选数、失败或待核来源，以及复核网页和报告路径。
遇到环境或验收失败时停止并报告；来源请求失败要列为缺口，不以模型生成内容替代。
```

## 复核已有结果（不重新抓取）

```text
使用“糖尿病会议采集与复核（Windows版）”技能，对我指定的运行编号执行--mode verify。
先检查项目环境；不要联网抓取，不重建最新草稿，不应用正式首页，不设置定时任务。
按脚本输出说明来源覆盖、证据、变化记录及产物是否通过验收。
若我未提供运行编号，先读取项目monitoring/latest.json中的run_id，再验证该轮，明确告诉我验证的编号。
```

项目路径变化时，替换上述项目目录。执行脚本需使用实际安装目录，不把这里的文件名当成客户端已安装位置。
